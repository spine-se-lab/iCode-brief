## 第二版的问题

第二版的 197 项 Compass 测试通过，但审核方的六个反例全部失败：混合工具调用句丢失编辑限制、修复 Compass 工具本身的任务消失、用户授权的 README 要求被删、单独故障句被兜底放回，以及两种正常禁止措辞被误删。两个旧测试的替身还缺少覆盖评估行，断言变绿并未证明维护成功。

因此，不能以第二版测试通过推断过滤规则正确。以下是第三版的行为与验证边界。

## 本轮改动

1. **工具分句收窄。** `task_messages` 只分离完整匹配“请调用/call/use/invoke + Compass 工具名”的无条件分句，以逗号、分号或句末为界。“只补测试，不改 pagination.py”保留；“修复 update_compass_brief”保留。带禁止或额外条件的调用保持原文。纯调用消息分离后若为空，也保留原文。原始 `user_inputs` 从未删除；这是提取输入的投影，不是执行或忽略工具调用的命令。
2. **故障背景保留。** 有界规则识别的肯定故障陈述移到现有 Goal `symptom`，保留原文、位置注释和 `reference_derived`，不猜测正确行为。用户原文中的条款和不确定措辞保留为有效 R/K；规范词表也补上 `n't`、不许、别。正常 fail-fast 描述不作为故障处理。该规则不是完整的自然语言分类器。
3. **展示与持久化。** 症状经 Goal 持久化、恢复后仍可查看。状态的 Goal 详情显示完整背景；普通 Brief 显示最多三条摘要并指向 `inspect_compass_brief(["goal"])`，紧凑 Brief 显示数量和详情入口。背景明确标注不等于当前已验证行为，且不进入 R/K 覆盖或冲突条目。
4. **来源不等于授权。** 逐字匹配到仓库上下文的 R 和 K 都保留，只给符合来源匹配条件的条目标注 `(repo)`。不再因用户没有逐字复述而删掉 README 要求。源码匹配仍是有界的文字匹配，不是语义归因。
5. **不再兜底复活。** 如果条目全部移入症状且没有有效 R/K，`update_compass_brief` 报告缺少要求并停止维护；症状保存在 Goal。不会把刚移走的故障句放回 R。
6. **测试替身返回完整评估。** 共享维护替身为每个当前 R/K 返回覆盖行；两个既有测试额外验证无维护错误、无降级标记、覆盖键及证据游标。`Check the Brief` 作为新用户消息仍触发下一次提取，是接受的现有行为，不是消除了额外模型调用。
7. **策略版本 5。** 从本开发树重新启动后，旧会话下一次更新会重新提取，保留历史 Brief。`/compass status` 仍只读，不触发迁移或模型调用。

保留第二版已经正确的改动：无效冲突引文逐行丢弃，同一窗口的其他有效结果可提交；工具说明保持三句；历史 Brief 导航保持不变。

## 仍未解决

- **旧 README 指令与最新范围冲突。** `(repo) Fix the pagination helper…` 与“只补测试，不改 pagination.py”仍可能同时出现。来源标注不会自动消除这类语义冲突。
- **近义和跨语言重复。** “不能删或放宽”与“不能删除或放宽”、同义中英文条目仍可能并存。
- **分类边界。** 有界规则不能识别所有故障描述或规范措辞。宁可保留不确定条款；症状移动也不能证明语义分类必然正确。
- **模型验证。** 本轮没有线上 GLM/DeepSeek 复验，没有安装到其他 host，没有提交或推送。

## 独立评测影响

提取后处理只在传入 `user_messages` 的交互路径执行；无此参数的独立评测保留模型原条目。此前新增的提取提示词及逐行冲突校验仍影响评测。本轮共享 Brief 渲染新增症状背景显示，改变文本和预算分配，也影响已有症状的独立评测；已在 `provenance.json` 登记源码摘要、适配 AST 和行为变化，不宣称与上游完全等价。
